# Выкат «Что у нас есть?»

Домен `zapas.burninghouse.ru`, порт внутри сервера `8799`, образ
`shadowkick/zapas:latest`, `client_id` — `zapas`.

Порядок важен: контейнер поднимается **до** nginx (скрипт в конце проверяет,
что домен отвечает именно этим сервисом), а клиент в Auth регистрируется до
первого входа.

## 1. DNS

`zapas.burninghouse.ru` → IP сервера, запись A. Без этого certbot не выдаст
сертификат.

```bash
dig +short zapas.burninghouse.ru
```

## 2. Зарегистрировать клиента в Auth

Один раз, на сервере, где крутится auth:

```bash
docker compose exec auth node server.js client-add zapas "Что у нас есть?" https://zapas.burninghouse.ru/
```

**Слэш в конце обязателен.** `redirect_uri` сверяется побайтово: без него
вход будет возвращать ошибку, а причина выглядит как «что-то сломалось в
auth». Проверить, что записалось:

```bash
docker compose exec auth node server.js clients
```

## 3. Образ

Compose в проде не собирает, а тянет готовый образ из Docker Hub. Его
публикует GitHub Actions при пуше в `main` — но **на пустом репозитории
образа ещё нет**, и `docker compose up` упадёт с «manifest unknown».

Варианта два:

- дождаться, пока пройдёт сборка в Actions (вкладка Actions в репозитории);
- или собрать прямо на сервере, если выкатываете раньше CI:

```bash
docker build -t shadowkick/zapas:latest .
```

## 4. Переменные окружения

Рядом с `docker-compose.prod.yml` нужен `.env` с общим секретом Admin. Файл
у сервисов общий на несколько ключей, поэтому правим его скриптом, а не
перезаписываем:

```bash
bash set-env.sh ADMIN_INTERNAL_KEY <тот же ключ, что у Admin>
```

Ключ **должен совпадать** с `ADMIN_INTERNAL_KEY` у Admin — иначе `/internal/*`
будут отвечать 403, Admin не увидит ни статистику, ни логи, а уборка данных
удалённых аккаунтов молча не заработает (сервис об этом пишет в лог при
старте).

Остальное уже прописано в `docker-compose.prod.yml`: `AUTH_ISSUER`,
`AUTH_CLIENT_ID`, `PUBLIC_URL`, `VAPID_SUBJECT`. Ключ GigaChat в проде не
нужен — справочник инструкций собирается на машине разработчика и едет в
образе.

## 5. Запуск

```bash
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml logs --tail=20
```

В логах должно быть две строки: про `ADMIN_INTERNAL_KEY` (если не задан) и
`Что у нас есть? слушает http://0.0.0.0:8799`. Проверка изнутри сервера:

```bash
curl -s localhost:8799/api/config
```

## 6. nginx и сертификат

```bash
sudo bash deploy/install-nginx.sh
```

Скрипт сам выпустит сертификат, уберёт старые конфиги этого домена в
`/root/nginx-backup-zapas-*`, проверит `nginx -t` и откатится, если не
сошлось.

**Про 80-й порт.** Сертификаты на этом сервере выпускаются через
`certbot certonly --standalone`, а standalone на время проверки поднимает
своего слушателя на 80-м порту. Этот порт занят nginx-ом — редиректом
http→https. Поэтому выпуск идёт с хуками:

```bash
sudo certbot certonly --standalone -d zapas.burninghouse.ru \
  --pre-hook "systemctl stop nginx" --post-hook "systemctl start nginx" \
  --deploy-hook "systemctl reload nginx"
```

Nginx гаснет секунд на десять. Важнее другое: **certbot сохраняет эти хуки в
конфиг продления**, поэтому через два месяца продление не упадёт с
«port 80 in use».

Плагин `--nginx` здесь не используется: `python3-certbot-nginx` на сервере не
установлен, и выпускать один сертификат иначе, чем соседние, — плохая идея.

### Соседние сертификаты

Те, что выпускали просто `certbot certonly --standalone -d домен`, хуков не
имеют. Пока nginx держит 80-й порт, их продление сломано — и узнаете об этом
не сразу, а когда сертификат протухнет. Скрипт в конце это проверяет и
называет такие домены поимённо. Проверить самому и починить разом:

```bash
sudo certbot renew --dry-run
printf 'pre-hook = systemctl stop nginx\npost-hook = systemctl start nginx\n' | sudo tee -a /etc/letsencrypt/cli.ini
```

`cli.ini` действует на все будущие запуски certbot, включая автоматическое
продление по таймеру. В конце он проверяет две вещи: что домен отвечает именно этим
сервисом и что **распознаватель кодов уезжает сжатым** (409 КБ вместо 925) —
gzip для `application/wasm` в конфиге есть именно для этого.

## 7. Admin

Чтобы сервис появился в админке, его нужно дописать в `SERVICES_JSON` у
Admin и передеплоить Admin:

```json
{"id":"zapas","name":"Что у нас есть?","baseUrl":"https://zapas.burninghouse.ru"}
```

Без этого ничего не сломается — просто Admin не будет показывать
статистику и логи, а health-check не станет следить за сервисом.

## 8. Watchtower

Метка `com.centurylinklabs.watchtower.enable: "true"` уже стоит в compose,
отдельной настройки не нужно — Watchtower (ставится один раз из репозитория
Auth, `deploy/watchtower-compose.yml`) сам заберёт новый образ после
следующей сборки в Actions.

## Проверки после выката

```bash
curl -s https://zapas.burninghouse.ru/api/config
curl -s https://zapas.burninghouse.ru/robots.txt
curl -s -o /dev/null -w '%{size_download}\n' -H 'Accept-Encoding: gzip' \
  https://zapas.burninghouse.ru/assets/vendor/zxing/zxing_reader.wasm
```

Ожидаемо: конфиг с `"clientId":"zapas"`, `Disallow: /` (аптечка закрыта от
поиска навсегда) и около 409 000 байт у последней команды.

Дальше руками, с телефона:

1. Открыть домен, войти — должно перекинуть на auth и вернуть обратно.
2. Добавить упаковку руками, проверить подсветку срока.
3. **Поднести коробку с DataMatrix к камере.** Камера работает только по
   https — на `http://` её не даст ни один браузер.
4. Установить на домашний экран (в Safari — «Поделиться» → «На экран
   "Домой"»).
5. Включить уведомления на вкладке «Дом» и нажать проверку.

## Нюансы, на которых легко потерять время

**Уведомления на iPhone приходят только установленному приложению.** Safari
не даёт web push обычной вкладке: сначала «На экран "Домой"», и уже оттуда
включать уведомления. На Android работает и во вкладке.

**Приглашения работают только между друзьями в Auth.** Сервис сверяет
список `GET /api/friends` перед тем, как создать приглашение, — своего
поиска людей у него нет. Если домашние ещё не подружились в кабинете
BurningHouse, список «кого позвать» будет пустым, и это не ошибка.

**Данные живут в томе `zapas-data`** — там и база `zapas.db`, и ключи
`vapid.json`. Удалить том = потерять аптечку и отвязать все подписки на
уведомления (браузеры подписаны на старый публичный ключ).

**Первое напоминание придёт не раньше следующего утра.** Планировщик шлёт
одно сообщение в день, в выбранное время по местному поясу; по умолчанию
10:00. Сразу после выката проверять нечего — для проверки есть кнопка на
вкладке «Дом».

**Каталог на `burninghouse.ru`** про новый сервис ещё не знает: карточка
добавляется в сервисе «Главная» отдельно.
