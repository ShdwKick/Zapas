# Справочник по кодам

`gtin.json` — что сервис знает о товаре по коду с упаковки:

```json
{
  "04601234567893": {
    "name": "Синупрет",
    "form": "капли для приема внутрь",
    "mnn": null,
    "afterOpenDays": 180,
    "storageMaxC": 25,
    "rx": false,
    "leafletUrl": "https://..."
  }
}
```

Это **часть образа, а не данные**: в рантайме сеть не нужна, обновление
справочника — новый образ. Пустой файл ничего не ломает: незнакомый код
просто спросит название один раз, и дальше дом помнит его сам.

Заполняется офлайн-инструментом `tools/leaflet.mjs` из официальных
инструкций — это **этап 3**, сейчас файл пустой. Правила заполнения и
почему поля приезжают с цитатами — в `../ARCHITECTURE.md`, раздел
«Инструкции».

Ключ — GTIN-14 строкой, с ведущими нулями: EAN-13 с упаковки дополняется
нулём слева (`assets/gs1.js`, `toGtin14`). Иначе один и тот же товар
окажется под двумя ключами.

## leaflets.json

Что сервис вычитал из официальных инструкций — ключ `regNumber`, то есть
номер регистрационного удостоверения:

```json
{
  "П N 014247/01": {
    "name": "Синупрет",
    "form": "капли для приема внутрь",
    "afterOpenDays": 180,
    "storageMaxC": 25,
    "rx": false,
    "quotes": { "afterOpenDays": "После вскрытия флакона: не более 6 месяцев." },
    "sha": "ed8641fe261d7fc2",
    "source": "sinupret-drops.pdf"
  }
}
```

**У каждого поля есть цитата, и она проверена**: `tools/leaflet.mjs` ищет её
в тексте самого PDF и выбрасывает поле, если не нашёл. Поэтому выдуманное
значение сюда не попадает — не «маловероятно», а технически.

`sha` — отпечаток PDF: инструмент не спрашивает модель повторно, пока файл
не изменился. `source` — имя файла, чтобы было понятно, откуда это взялось.

Сервис подставляет отсюда `afterOpenDays`, `storageMaxC` и `rx`, когда
человек заводит позицию с **точно таким же** названием. Нестрогое совпадение
здесь недопустимо: «Нурофен» и «Нурофен Форте» — разные препараты, и
подставить одному срок другого хуже, чем не подставить ничего.
